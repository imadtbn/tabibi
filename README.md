# طبيبي — دليل الأطباء في الجزائر

دليل عربي RTL ثابت على GitHub Pages: صفحات تخصصات مستقلة، بحث ومفضلة، خريطة عند الطلب، وPWA. يعمل دون قاعدة بيانات خلفية أو أسرار في المتصفح.

## تشغيل وبناء

Python 3.12+ وNode.js 22+، دون تثبيت حزم npm:

```sh
python3 tools/build.py
npm test
python3 -m http.server 8080
```

افتح localhost:8080. لا تستخدم file://. ملفات HTML وSW وفهارس البيانات نواتج مُلتزم بها في Git حتى يعمل النشر الحالي من main دون تغيير إعدادات Pages.

## قاعدة البيانات حسب التخصص

المصدر الآن 20 ملفًا داخل `data/doctors/`، مثل `cardio.json` و`dental.json`. كل ملف مصفوفة سجلات تخص معرف تخصص واحد. عدّل هذه الملفات، لا search-index أو stats أو صفحات HTML المولدة.

- `data/specialties.json`: معرّفات التخصصات وأسماؤها ومساراتها.
- `data/wilayas.json`: قائمة الرموز المستخدمة؛ راجع المرجع الرسمي عند توسعتها.
- `data/communes.json`: مرجع البلديات الأساسي.
- `data/locations.json`: ناتج البناء، يضم المرجع الأساسي وأسماء البلديات المضافة مع السجلات.
- `data/search-index.json`: فهرس مختصر للبحث والترتيب والفلترة والخريطة، دون هواتف أو ساعات عمل أو كامل تفاصيل العنوان.
- `data/stats.json`: أعداد إجمالية ومجمّعات للجداول لحساب التوفر دون تنزيل ملفات الأطباء.

صفحة التخصص تحمّل ملف تخصصها فقط. صفحة البحث العام تستخدم الفهرس المختصر وتحمل ملفات التخصصات اللازمة للبطاقات المعروضة على دفعات 12. تُشارك الطلبات داخل الصفحة، ولا يكرر البحث تنزيل الملف نفسه. الخريطة تستخدم نقاط الفهرس المختصر.

## حالة السجلات الحالية

نُقلت السجلات الأربعون السابقة إلى ملفات التخصصات كبيانات أولية `verificationStatus: "unverified"`. بقي `isPlaceholder: true` لأن الأسماء والعناوين والهواتف السابقة نماذج، ولا يجعلها نقل الملفات حقيقية. يمكن لصاحب الموقع استبدالها يدويًا. لا تُختلق مصادر أو تواريخ تحقق.

- `unverified`: بيانات أولية غير متحقق منها؛ لا تاريخ verifiedAt ولا Physician في JSON-LD، وصفحة الملف الشخصي noindex.
- `verified`: تتطلب مصدر HTTPS وتاريخ تحقق حقيقي بعد مراجعة بشرية، ولا يمكن أن تكون placeholder.
- السجلات المسماة «نموذج» ليست أطباء حقيقيين. أرقام +213000000xxx غير حقيقية؛ إحداثياتها نقاط بمراكز مدن لا تمثل عيادات.
- عند تعديل سجل عبر المحرر يُعاد إلى unverified؛ الإقرار بأن المعلومات حقيقية لا يمنحه التوثيق.

السجل: id ثابت، slug لاتيني فريد، name، specialtyIds من عنصر واحد مطابق لاسم الملف، verificationStatus، updatedAt، ومصفوفة practices. لكل مكان: wilayaCode وcommuneId أو communeName والعنوان وphones دولية وcoordinates أو null وopeningHours أو null. يمكن الاحتفاظ بأكثر من عيادة للطبيب.

## صفحة إضافة وتعديل طبيب

`add-doctor.html` متاحة من الهيدر. هي محرر محلي، وليست لوحة تحكم متصلة بالخادم:

1. اختر التخصص؛ سيُحمّل ملفه وحده.
2. أضف طبيبًا أو اضغط تعديل بجانب سجل موجود.
3. أدخل الاسم، الولاية، البلدية، الشارع، الهواتف، الإحداثيات الاختيارية، وأيام وساعات العمل. يدعم النموذج فترتين يوميًا ويحافظ على العناوين والهواتف والفترات الإضافية الموجودة عند تعديل السجل.
4. احفظ المسودة. تبقى على المتصفح الحالي ولا تظهر للزوار أو في البحث العام قبل النشر.
5. نزّل ملف التخصص JSON؛ يجمع أحدث السجلات المنشورة والتعديلات المحلية. يُرفض التصدير عند وجود تعارض مع تعديل أحدث في المستودع، أو إذا لم تحفظ النموذج.
6. استبدل الملف المناظر في `data/doctors/` ثم شغّل build وtest وارفع البيانات **وجميع النواتج** إلى المستودع.

الاستيراد يقبل مصفوفة سجلات من نفس التخصص، حتى 2 MiB/5000 سجل، ويدمجها حسب id دون حذف الآخرين. «إلغاء التعديل المحلي» يستعيد السجل المنشور أو يزيل المسودة الجديدة من الجهاز فقط. لا ترسل الصفحة طلبات كتابة إلى GitHub ولا تجمع كلمات مرور أو رموز وصول. النشر العام التلقائي يحتاج خدمة خلفية مصادقًا عليها؛ ليس جزءًا من هذا الإصدار.

إذا تغيّر سجل في الخادم أثناء تعديله: أعد تحميل الملف، ألغ التعديل المحلي المتعارض ثم أعد إدخال التغيير بعد مراجعة النسخة المنشورة. التصدير يتحقق من أحدث نسخة متاحة على الشبكة، أو النسخة المحفوظة عند انقطاعها؛ راجع الملف قبل النشر.

## الواجهة والوقت

البطاقات تعرض الأيقونة والتخصص والعنوان والأيام والساعات، هاتف LTR قابل للنقر، ومسار Google Maps. الساعات وفق Africa/Algiers مع تحديث الشارة كل 30 ثانية وعند العودة إلى التبويب. اليوم [] مغلق، اليوم المفقود مجهول. قسّم الفترات الليلية بين اليومين. حالة «متوفر» تعكس الجدول فقط ولا تؤكد وجود موعد.

المسافات بخط مستقيم؛ إحداثيات المستخدم لا تُحفظ دائمًا. لا يفتح الموقع خرائط خارجية أو اتصالًا هاتفيًا دون ضغط المستخدم. Leaflet والخط Tajawal محليان مع الرخص، وبلاطات OpenStreetMap لا تُحمّل قبل فتح الخريطة ولا تُخزّن دون إذن مزودها.

## PWA والأداء

Manifest ذو مسارات نسبية وأيقونات 192/512 وmaskable. عامل الخدمة معزول بنطاق المشروع. يخزن الغلاف الأساسي والفهرس والملخص، لكنه **لا ينزل جميع ملفات الأطباء أو ملفاتهم الشخصية أو صفحات تخصصاتهم أثناء التثبيت**. تُخزن تلك الملفات عند زيارتها فقط، وتكون متاحة لاحقًا دون اتصال. تخصص لم يُفتح سابقًا قد لا يعمل دون شبكة.

ينشأ إصدار SW من بصمة المحتوى. يظهر إشعار تحديث للمستخدم، وتحذف النسخة الجديدة مخازن طبيبي القديمة فقط. البيانات والتنقل network-first؛ الأصول ثابتة لكل نسخة. العمل دون اتصال لا يؤكد حداثة ساعات العمل.

## SEO

يولّد build عناوين وأوصاف وcanonical وOpen Graph وJSON-LD وخريطة الموقع. صفحات الأطباء غير المتحقق منهم وصفحة المحرر والمفضلة والصفحات التقنية noindex. ما دام الدليل يحتوي سجلات أولية، لا تُفهرس صفحات القوائم والتخصصات التي تعرضها. عند استكمال البيانات والتوثيق تُعاد فهرستها بعد البناء.

**GitHub Pages:** الزواحف تعتمد `https://imadtbn.github.io/robots.txt` في جذر النطاق، وليس `/tabibi/robots.txt`. أضف سطر Sitemap إلى robots الخاص بمستودع جذر النطاق مع الحفاظ على قواعد بقية المشاريع:

```text
Sitemap: https://imadtbn.github.io/tabibi/sitemap.xml
```

## الاختبارات

`npm test` يفحص جميع الصفحات والأصول والمسارات وMetadata وManifest وSitemap وصياغة JS، والبحث والتوفر والمسافات، وفصل التحميل حسب التخصص، والتحقق والاستيراد ودمج التعديلات والتعارضات، والتخزين عند الطلب لعامل الخدمة. اختبارات SW محاكاة في Node، وليست ادعاء بتثبيت فعلي على هاتف أو قياس Lighthouse.
