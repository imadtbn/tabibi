# طبيبي — دليل الأطباء في الجزائر

موقع عربي RTL ثابت متوافق مع GitHub Pages. صفحات HTML مُولّدة مسبقًا، بحث محلي، مفضلة، خريطة تُحمّل عند الطلب، وPWA للعمل دون اتصال.

## التشغيل والتحديث

يتطلب Python 3.12+ وNode.js 22+ للاختبارات، دون حزم npm.

```sh
python3 tools/build.py
npm test
python3 -m http.server 8080
```

افتح `http://localhost:8080/`. لا تستخدم `file://` لأن تحميل JSON وService Worker يتطلبان HTTP/HTTPS. للنشر ارفع الملفات الناتجة إلى فرع GitHub Pages الحالي. الملفات المولدة مُلتزم بها كي يستمر النشر الحالي دون تغيير إعدادات الاستضافة.

## البيانات

- `data/specialties.json`: 20 تخصصًا، معرّف ثابت ومسار واسم عربي وفرنسي ومرادفات.
- `data/wilayas.json`: قائمة الرموز 01–58 المستخدمة في النسخة الأصلية، مع تصحيح مطابقة 49–58. هذه ليست مطالبة بأن التقسيم الإداري لن يتغير؛ راجع المرجع الرسمي قبل توسيع البيانات.
- `data/communes.json`: أضف البلديات بمعرّفات ثابتة و`wilayaCode` من مصدر موثوق.
- `data/doctors.json`: المصدر الوحيد لسجلات الأطباء المنشورة. أماكن الممارسة متعددة داخل `practices`، دون تكرار الطبيب.
- `data/search-index.json` و`data/stats.json`: نواتج البناء؛ لا تُعدّل يدويًا.

البيانات الأربعون السابقة مولّدة عشوائيًا وفق السكربت القديم، وقد أزيلت من العرض العام؛ تبقى في تاريخ Git. لهذا الدليل فارغ حاليًا. لا تملأ الفراغ بأسماء/هواتف/تقييمات تجريبية. عدم وجود نتائج حالة مدعومة وصريحة في الواجهة.

كل سجل منشور يتطلب: `id` نصي فريد، `slug` فريد لاتيني، `name`، `specialtyIds`، `verificationStatus: "verified"`، `sourceUrl` HTTPS يشير إلى مصدر علني صالح، `verifiedAt` بتاريخ حقيقي، و`practices` تحتوي `wilayaCode` و`address` و`phones` بصيغة دولية، و`coordinates` (lat/lng) أو null. `communeId` اختياري حتى يتوفر مرجع بلديات موثق. `openingHours` اختياري ويحتوي أيام `sat`…`fri` ومصفوفات فترات `["08:00","12:00"]`؛ فترة مغلقة `[]`، يوم مجهول يُحذف. الفترات الليلية تُقسم بين يومين. تحقق بشري من المصدر مطلوب؛ فحص البناء يتحقق من البنية ولا يصادق طبيًا على المعلومة.

يُنشئ البناء لكل طبيب صفحة مستقلة وبيانات منظمة من الحقائق نفسها. يُظهر الوقت وفق Africa/Algiers، وفي وضع عدم الاتصال تصبح المواعيد غير مؤكدة. المسافة بخط مستقيم، لا تمثل المسار أو زمن الوصول.

## الصفحات والتنسيق

`tools/build.py` هو مصدر قوالب الصفحات والهيدر والفوتر. عدّل القالب ثم أعد البناء. يتضمن 20 صفحة تخصص مستقلة، وصفحة انتقال متوافقة مع روابط `specialty.html?spec=...` السابقة.

`css/style.css` يحتوي التصميم المتجاوب والوضع الليلي. الخط Tajawal مستضاف محليًا مع رخصته في `assets/fonts/OFL.txt`. Leaflet 1.9.4 محلي مع رخصته. بلاطات OpenStreetMap تُطلب فقط عند عرض الخريطة؛ لا يخزن Service Worker بلاطات الخرائط ولا يجلب مناطق مسبقًا. حافظ على الإسناد والتزم بسياسة مزود البلاطات قبل زيادة الحمل الإنتاجي.

## PWA

- `manifest.webmanifest`: هوية التطبيق، نطاق ومسار بدء نسبيان، أيقونات 192/512 وmaskable واختصارات.
- `js/pwa.js`: التسجيل من أي عمق، التثبيت حسب دعم المتصفح، إشعار تحديث اختياري، وإرشادات Safari.
- `tools/sw-template.js`: مصدر عامل الخدمة؛ `sw.js` ناتج بناء بنسخة مشتقة من المحتوى.
- التخزين محدد بنطاق المشروع ولا يمس مخازن المواقع الأخرى على نفس النطاق.
- تُحفظ الصفحات العامة والتخصصات والموارد محليًا. التنقل والبيانات يجربان الشبكة أولًا ثم النسخة المخزنة. موارد التطبيق الأساسية محفوظة لكل إصدار.
- ملفات البيانات دون اتصال قديمة بطبيعتها؛ يظهر تنبيه. عند التوسع الكبير، انتقل إلى حفظ الصفحات المستخدمة فقط بدل تخزين كل صفحة طبيب.
- لا إشعارات دفع، لا تخزين للموقع الجغرافي، ولا تخزين لبيانات مرضى.

## SEO وrobots.txt

تُولّد عناوين وأوصاف وcanonical وOpen Graph وJSON-LD و`sitemap.xml` من القوالب. المفضلة والصفحات التقنية و404 وصفحة التخصص القديمة تحمل `noindex` ولا تدخل Sitemap. لا يُختلق تاريخ `lastmod`.

**قيد GitHub Pages:** محركات البحث تقرأ robots من `https://imadtbn.github.io/robots.txt` فقط. الملف `https://imadtbn.github.io/tabibi/robots.txt` لا يتحكم في الزحف لأنه داخل مجلد. يلزم دمج سطر Sitemap أدناه في ملف robots بجذر النطاق (مستودع `imadtbn.github.io`) مع الحفاظ على قواعد المشاريع الأخرى. لم يُعدّل هذا المشروع ذلك المستودع الآخر.

```text
Sitemap: https://imadtbn.github.io/tabibi/sitemap.xml
```

يمكن إرسال عنوان Sitemap مباشرة في Google Search Console. وجود Sitemap وSchema لا يضمن الفهرسة أو النتائج المحسنة. راقب الصفحات قليلة المحتوى عندما تبدأ إضافة بيانات فعلية.

## الاختبارات والحدود

`npm test` يفحص جميع روابط الملفات المحلية وmeta وcanonical وJSON-LD وأصول CSS والManifest والSitemap وصياغة JavaScript، واختبارات بحث ومسافات وساعات العمل، واختبارات Service Worker في محاكاة Cache/Fetch لـ Node.

اختبارات عامل الخدمة ليست بديلًا عن اختبار التثبيت الحقيقي على Android/iOS. اختبر التثبيت، فتح صفحة تخصص دون اتصال، وظهور تحديث بعد نشر إصدار جديد. أهداف الأداء بعد قياس الاستخدام: LCP ≤2.5s، INP ≤200ms، CLS ≤0.1. لا توجد نتائج Lighthouse مثبتة في هذا المستودع حتى الآن.

التواصل حاليًا عبر GitHub Issues (علني)، وليس نموذجًا يدّعي إرسال رسائل. لا أدوات تتبع أو إعلانات مفعلة في هذا الإصدار. عند إضافة بيانات/إعلانات/مزود رسائل جديد راجع الخصوصية وسلوك التخزين.
